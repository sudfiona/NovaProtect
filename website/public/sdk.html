NovaProtect SDK

函数 / 区域加密 SDK

在应用源码里标记需要虚拟化或混淆的函数，再用 NovaProtect 客户端打包，标记区域即被降级为 VM 字节码。

下载客户端

快速开始

  1. 把 sdk/include/novaprotect_sdk.h 放进你的工程。
  2. 用 NOVAPROTECT_BEGIN("名称") 和 NOVAPROTECT_END() 包住一个函数体。
  3. 正常编译出 EXE——标记在未保护版本里是无副作用的 NOP。
  4. 在 NovaProtect 客户端选择该 EXE，模式设为虚拟化或 Ultra，开始保护。
  5. 客户端会扫描 BEGIN/END 字节边界、在对象编辑器列出每个区域，并把可翻译区域降级为 VM 字节码。

手动添加函数保护（无需改源码）

除 SDK 标记外，客户端「保护」页内置 VMP 式函数扫描器：对 x64 目标读取 .pdata 异常目录枚举全部运行时函数（含静态函数），逐个勾选或一键「添加所有函数」即可对整个函数体 做 VM 保护。列表显示名称 / 地址 / 节 / 大小 / 可虚拟化性，支持批量设置模式、VM 复杂度、变异强度与激活锁定。

  • 函数级虚拟化只虚拟化到第一个 RET 之前，尾跳落在 RET 上由原生指令返回，调用约定不变。
  • 区域表上限 64，超出按 RVA 顺序取前 64 个，其余保持原生。
  • 访问栈帧 / 内存 / 32 位操作数形式的函数会被安全跳过，程序功能不受影响。

标记示例（C/C++）

#include "novaprotect_sdk.h"

int secret_calc(int x)
{
    NOVAPROTECT_BEGIN("secret_calc");
    int a = x + 3;
    int b = x - 7;
    int c = (a ^ b) * 0x9E3779B9 + a;
    NOVAPROTECT_END();
    return c;
}

完整虚拟化的约束

VM 解释器只处理纯寄存器、直线型的 x86-64 子集。区域一旦访问 RSP/RBP 或内存，打包器会安全地保留为原生代码。要真正虚拟化关键函数，用寄存器直通的手写汇编块（见 sdk/examples/example_vm.S），并保证块长足够容纳运行时 trampoline。

反沙箱 / 反转储 / 环境自检

打包时可在客户端独立开启三项运行时防护：

  • 反沙箱检测：累计评分 CPU 数、物理内存、已知沙箱模块与监控组件、RDTSCP 时序、CPU 核掩码、睡眠压缩与桌面/用户名模板，超过阈值即终止。
  • 反内存转储：校验 MZ/PE 头、区段表与 PEB 加载基址，拦截 Procdump/Minidump 后处理。
  • 交互桌面环境自检：校验 CPU 数、内存、开机时长、屏幕分辨率、显示器数。

这些只对原生 x64 生效，且默认关闭，按需开启避免误杀。

与商业 VMProtect 的关系

客户端自身与 NovaProtect 核心运行时使用商业 VMProtect SDK 做启动级虚拟化与防篡改（构建时自动链接 VMProtectSDK64.a，发布时附带 VMProtectSDK64.dll）。这是对 NovaProtect 自有 VM 引擎的补充。

兼容性

旧版 NOVAPACK_BEGIN/NOVAPACK_END 继续可用，字节模式不变。x86 与 x64 都支持 marker 扫描；VM 翻译仅 x64。

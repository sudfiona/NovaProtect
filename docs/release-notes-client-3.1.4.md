## 一句话概括

3.1.4 把虚拟化推到头：同一目标实测**虚拟化覆盖率与 vm 字节覆盖率双双 100.0%**——
5266 个函数、5351 个 chunk 全部可虚拟化、零拒绝桶。顺手修掉 12 个缺陷，其中 3 个
会让已发布版本的保护结果或检测行为出错。

## 覆盖率：100.0%

| 指标 | 结果 |
| --- | --- |
| 可虚拟化 chunk 占比 | 5351 / 5351（100.0%，零拒绝桶） |
| vm 字节覆盖率 | 1,589,043 / 1,589,307（100.0%） |

测量由 `tools/vmcoverage` 直接调用真实翻译器完成，不是估算。两口径在
3.1.2 发布时是 91.5%（旧测量模型），本轮起点 88.1%（校正模型）。

## 新增：帧序言与尾声进 VM

以前栈帧函数的序言（push rbp / mov rbp,rsp / sub rsp,N）和尾声（leave / ret）留在
原生侧，函数体才进 VM。现在**整段函数体都虚拟化**：

- `push` / `leave` / `ret`（含 `ret imm16`）、`enter`、`pushfq` / `popfq`、
  8 位乘除对（`mul/div r/m8`）全部降低为 VM 指令执行；
- 多返回、共享尾声、尾调用全部正确，栈帧访问（`[rbp-X]` / `[rsp+X]`）原生支持。

## 新增：原生桥

降不了的指令形式不再让整个函数放弃虚拟化——chunk 在该指令前停止，指令按原生语义
在两个 VM 区之间执行，随后继续开新 chunk：

- AVX/VEX/EVEX（长度已精确解码，切分位置准确）
- `cmpxchg8b/16b` 与寄存器-寄存器 `cmpxchg`——**刻意留在原生侧**：它们是原子原语，
  任何 VM 合成都会丢跨线程原子性
- 16 位 `push`/`pop`、`enter` 嵌套帧、`__chkstk`/alloca 形态的动态栈深

实测目标里这些形式零出现，字节间隙仅 264 字节（桥指令 + 尾部不对齐）。

## 修复（12 项，3 项影响已发布版本）

| 问题 | 影响 | 根因 |
| --- | --- | --- |
| 整数 SIMD（PADDB 等）被静默跳过 | **3.1.2/3.1.3 虚拟化结果错误** | XALU 整数通道是空操作 |
| POR 执行成 PSRAW 的语义 | **3.1.2/3.1.3 虚拟化结果错误** | 映射键写成 0xE1（PSRAW 的编码） |
| 反调试检测恒失效或砸栈 | **2.4.0 起带反调试的保护输出** | NtQueryInformationProcess 的 ReturnLength 指针写错栈槽（x64 第 5 参在 `[rsp+0x20]` 却写到 0x28），内核往栈残留地址写字节 |
| `push reg/imm` 虚拟化恒存 0 | 本轮特性内部缺陷 | PUSH 降低误读操作数方向 |
| `bt r/m, imm8` 被空译 | 本轮特性内部缺陷 | 组扩展被解码成幻影 RSP，触发假切分 |
| 标志恢复覆盖 rax | 本轮特性内部缺陷 | 出口 popfq 插入位置错误 |
| 指令流失步两处 | 覆盖率损失 | `66 F7` TEST 立即数宽度、`0F 31` rdtsc 误加 ModRM |
| 主题颜色切主题后不全局、按钮/胶囊成椭圆、三主题不够鲜明 | **客户端外观** | 主题体系重写：颜色原位全局生效；冷雾/热浪/深空色温对撞 × 时代质感融合——玻璃（冰蓝全息+软圆角）、波普（珊瑚品红平涂+黑描边+直角+Bahnschrift）、实验室（黑紫+磷光绿/紫外+Cascadia Mono） |
| 其余 4 项 | 翻译缺口 | imul 16 位立即数、xchg RIP 内存、PMULLW 映射、rdseed/rdrand 前缀判定 |

## 已知边界（如实声明）

- **桥指令字节不计入虚拟化字节**：走原生桥的指令按原生语义执行，行为正确但不进 VM。
- **x87 经原生语义执行**：按 (esc,modrm) 原始编码查表运行，不建模 x87 栈——编译产出的
  80 位 long double 语义保持逐位一致。
- **驱动加载未验证**：能编译、能链接，测试签名加载需要真机开启测试模式并重启，
  发布环境未执行。

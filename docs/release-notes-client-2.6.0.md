# NovaProtect 客户端 2.6.0 更新日志

发布类型：客户端（桌面程序）· 版本 `2.6.0` · 2026-11-04

本文是面向使用者的更新说明，可直接作为 GitHub Release 正文使用。引擎侧的实现细节见
`CHANGELOG.md` 的 `## 2.6.0` 一节。

---

## 一句话概括

2.6.0 把「对抗与规避」从只能在命令行里传参数，变成客户端里能看见、能调、能审计的一页；
并给客户端自身加了一页更新日志。之前这些能力都在引擎里，界面上一个控件都没有。

---

## 新增：对抗与规避页

一个独立页面，保护项目页顶部有一张摘要卡显示当前档位，「调整」按钮直接跳过来。

**规避档位**

四档：关闭 / 均衡 / 激进 / 偏执。每档的实际展开值以四列对比表列出，当前档位列在表头标记
「当前」。三个非关闭档位的差别如下：

| 字段 | 均衡 | 激进 | 偏执 |
| --- | --- | --- | --- |
| 垃圾指令密度 | 1 | 3 | 5 |
| 反沙箱级别 | 1 | 2 | 3 |
| 反调试级别 | 1 | 2 | 3 |
| 引爆延迟 | 1500 ms | 3000 ms | 5000 ms |
| 内存流式解密轮数 | 1 | 2 | 3 |
| 内存解密窗口 | 4096 B | 4096 B | 2048 B |
| 驱动探针层级 | 1 | 2 | 3 |
| 驱动自摘链 | 否 | 否 | 是 |

静态特征清洗（Rich 头、时间戳、PDB、节区改名、留白填充、无效签名清理）在三个非关闭档位
上一律开启——留着这些特征会让其余工作白做，而且不增加运行开销。

**构建签名种子**

种子决定标签、nonce、节区后缀、填充与探测顺序。

- 留空：每次构建从系统熵取新值，两次构建不共享字节特征
- 填固定值：可复现同一构建，便于定位问题
- 界面校验 1–16 位十六进制且不等于 0，格式不对不许保存
- 「每次构建重新随机」开关可强制忽略种子

**动态对抗**

垃圾指令密度（0–8）、反沙箱级别（0–3）、内存流式解密轮数（0–3）、引爆延迟
（0–15000 ms，步长 250）、API 反挂钩开关。每项都有一句说明它做什么、代价是什么。

**内核与 hypervisor**

- 驱动探针层级 0–3，每档附独立说明（关闭 / 仅工件 / 加 tick 连续性 / 全开含自摘链）
- CPUID 退出代价探测开关

**环境闸门**

沙箱分数阈值、无头环境分数阈值（各 0–100），以及六个硬件下限：逻辑处理器数、物理内存、
系统运行时长、屏幕宽度、屏幕高度、显示器数量（0 = 不检查）。

这些阈值只在保护项目页开启「沙箱防护」或「环境检查」时才参与判定，页面里写明了这点。

**本机审计**

两个按钮，直接通过完整的客户端调用握手调用引擎，打印真实本机结论：

```
审计本机 hypervisor
  hypervisor PRESENT vendor=Microsoft Hv cpuid=1448c storm=23180c
  EXIT-COST-ANOMALY score=85

审计本机内核工件
  kernel artifacts 0/40 (device 0, service 0, module 0) tick=plausible score=0
```

审计只读取本机状态，不改动任何文件，不需要管理员权限。

## 新增：构建可追溯

以前无法回答「这个已产出的文件是哪套参数压出来的」。现在：

- 构建日志新增两行：`规避: <档位> · <详情>`，以及构建结束后的 `命令行: <完整 argv>`
- 构建计划 JSON 新增 `evasion`、`environment`、`commandLine` 三个字段

实测发出的命令行（档位在前、逐字段覆盖在后）：

```
-evasion balanced -junk 2 -anti-sandbox 2 -detonate-delay 2500 -memstream 2 \
-unhook 1 -kernel-level 2 -hv-exit-cost 1 -sandbox-threshold 40 -env-threshold 7
```

顺序不能反：`-evasion` 会把引擎的整个规避配置重写成该档位默认值，放在逐字段覆盖之后
会把用户调的值悄悄盖掉。

## 改进

- **默认页改为保护项目**。以前打开停在设置页，而设置页没有任何要做的事。
- **设置页新增「数据与诊断」**：打开日志目录、打开配置目录、一键恢复默认规避设置，
  并直接显示两个路径，不用去猜。
- **项目文件 schema 2 → 3**，带上规避与环境闸门。打开旧项目不会崩：缺失或为 null 的块
  会补成默认实例，v1 项目照旧走原有迁移。
- **跑之前先校验种子**。引擎遇到零种子会以 exit 2 退出，界面现在会提前拦下并指出字段。

## 修复

| 问题 | 根因 |
| --- | --- |
| 导航到新页面时窗口直接崩溃 | WinUI 在 `InitializeComponent` 解析控件树时就会触发 `SelectionChanged` / `ValueChanged`，处理器去读还没构造出来的兄弟控件 |
| 双击「开始保护」把整个窗口打崩 | `ContentDialog` 同一时刻只允许一个，第二次调用抛 `COMException` 且无人捕获。改为统一串行化，第二个请求排队 |
| 规避摘要卡显示「均衡 · 均衡 · …」 | 档位名被 `Summary` 和调用处各加了一次 |
| 档位明细表看起来每行都一样 | 只显示当前档位一列，均衡档 16 行里 12 行都是「是」。改为四档并排对比 |

## 已知限制

- **驱动加载未验证**。当前状态准确表述是「能编译、能链接、能签名、链能验，加载未验证」。
  真机加载需要开启测试签名模式并重启，这一步没有在发布环境中执行。
- **VM 虚拟化需要目标里有可下降低区域**。没有 SDK marker 也没勾选函数的普通 EXE，
  会走原生执行而不是虚拟化，构建日志会明确写出 `VM: 0 region(s) virtualized`。
- **偏执档兼容性风险最高**。所有探测全开、垃圾指令拉满、驱动退出时自摘，发布前必须在
  目标环境实测。
- **反沙箱与反调试可能误触发**。在低配真机、远程桌面、部分虚拟化的办公环境里，
  阈值设得太严会把正常环境判成分析环境。
